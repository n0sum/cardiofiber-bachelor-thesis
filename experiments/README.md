# Experiments

One `.conf` file per experiment. The executable takes one or more and
writes a CSV of per-face errors for each, in sequence:

```bash
./estimator/build/Estimate output/aniso_zone_1/confs/sub_0-1-2.conf output/aniso_zone_1/confs/sub_0-1-3.conf
```

The `.conf` files are generated by `subsets.py`, with `write_conf`: the lines of
`template.conf` (the thresholds, the same for all) plus `lat_ply`,
`ground_truth_ply`, `maps` and `output_csv`. They are not in git: the
recipe is the script.

## Format

`key = value`, one per line, with spaces around `=` and no spaces in the
value, as `subsets.py` and `template.conf` write them. Empty lines and lines
starting with `#` are skipped.

| key                         | meaning                                       |
|-----------------------------|-----------------------------------------------|
| `lat_ply`                   | mesh + LAT maps: the input of the estimator    |
| `ground_truth_ply`          | per-face fibers, true CVs and region tags      |
| `maps`                      | comma-separated site indices                   |
| `mask.min_singular_value`   | threshold on the smallest singular value of the per-face system |
| `output_csv`                | where to write the per-face errors             |

All 5 keys are required.

`ground_truth_ply` is `data/reference/LA_GT_NAME.ply` of the scenario
that produced `lat_ply`: per-face fiber, CV_L, CV_T and tag, read as
they are.

## Scenarios

A scenario `aniso_zone_N` is the mesh divided into N random zones, each with the CVs
of one row of `region_cv/aniso_random.csv`. Why N = 1, 8, 70, 600: main README,
*Reproducing the results*. `run_all.sh` builds all four; to build one by hand
(here N = 70), from the repository root with the `cardiofiber` environment active:

```bash
python simulator/stage1/opencarp/mm_to_um.py
python simulator/stage1/opencarp/random_tags.py aniso_zone_70 experiments/region_cv/aniso_random.csv 0 70
python simulator/stage1/opencarp/run_sims.py aniso_zone_70 experiments/region_cv/aniso_random.csv data/reference/aniso_zone_70/LA_um
python simulator/convert/toPly.py aniso_zone_70 experiments/region_cv/aniso_random.csv data/reference/aniso_zone_70/LA_um
```

| step | writes |
|---|---|
| `mm_to_um.py` | `data/reference/LA_um.*`: the AugmentA mesh in um (once for all scenarios) |
| `random_tags.py NAME CSV SEED N` | `data/reference/NAME/LA_um.*`: same mesh, the zone tag of each face in the `.elem` |
| `run_sims.py NAME CSV MESH_BASE` | `data/reference/sims/NAME/run_k/`: one openCARP run per pacing site k |
| `toPly.py NAME CSV MESH_BASE` | `data/reference/LA_LAT_NAME.ply` (mesh in mm, maps `lat_0` … `lat_5`) and `data/reference/LA_GT_NAME.ply` (true fiber and CVs per face) |

## Running the estimator

```bash
python experiments/subsets.py aniso_zone_70                  # one .conf per subset of >= 3 maps
./estimator/build/Estimate output/aniso_zone_70/confs/*.conf  # one errors.csv per .conf
```

To run a single subset, e.g. maps 0, 2, 4, pass its `.conf`:
`./estimator/build/Estimate output/aniso_zone_70/confs/sub_0-2-4.conf`.
A `.conf` written by hand works too, but the folder of `output_csv` must already exist:
Estimate does not create it (`subsets.py` does).


## Non-estimable faces

Each face uses all the maps of `maps`, one row per map in its linear system.
It is non-estimable if it has fewer than 3 maps, if the smallest singular value of the
system does not exceed `mask.min_singular_value` (nearly parallel fronts) or if
the smaller eigenvalue of the estimated tensor (CV_T^2) does not exceed 1e-8 times
the larger one (CV_L^2): a test of numerical zero, CV_T / CV_L > 1e-4, not a physical
threshold (`kMinEigenRatio` in `cardiofiber/src/Mesh.cpp`).

Negative LATs (-1: node not reached by the FIM) are rejected upstream, by
`simulator/convert/toPly.py`, before writing `lat_ply`.

## Output CSV

One row per face, no aggregation. Columns, in order:

| column          | meaning                                                |
|-----------------|--------------------------------------------------------|
| `face_id`       | index of the face in the mesh                           |
| `area`          | area of the face, mm^2                                  |
| `estimable`     | 1 if the face is estimable, 0 otherwise                 |
| `cond`          | condition number (see below); empty if not computed     |
| `CV_L_est`      | estimated longitudinal CV, mm/ms; empty if not estimable |
| `CV_T_est`      | estimated transverse CV, mm/ms; empty if not estimable  |
| `CV_L_true`     | true longitudinal CV, mm/ms                             |
| `CV_T_true`     | true transverse CV, mm/ms                               |
| `err_angle`     | fiber angle error, `acos(|a.b|)` in degrees; empty if not estimable |
| `err_cv_l`      | relative error of CV_L, `100 (CV_L_est - CV_L_true) / CV_L_true`, %, signed; empty if not estimable |
| `err_ratio`     | relative error of r = CV_L / CV_T, `100 (r_est - r_true) / r_true`, %, signed; empty if not estimable |

The errors are computed where the CSV is written, in double, with the same formulas in
`exportErrorsAsCsv` (`estimator/src/GroundTruth.cpp`) and in `estimator/roney.py`.

The CSV of `estimator/roney.py` additionally has, after `estimable`, the column
`k_used`: the maps of the triplet that pass the planar fit in the patch of the
face (0-3). With `k_used < 3` the face is not estimable because of the fit; with
`k_used = 3` and `estimable = 0` the conic is not an ellipse or the system is
nearly singular.

`cond` is `sigma_max / sigma_min`

Scenario, method and subset of an `errors.csv` are given by its folder,
`output/SCENARIO/METHOD/sub_…/`, not by its columns. `analysis/analysis.py`
reads one `errors.csv` at a time.

## The experiment grid

`output/` has one folder per scenario `aniso_zone_N` (the list `ZONES` in
`run_all.sh`) and two folders for the whole grid, made once:

```
output/
  aniso_zone_N/                  one per scenario
    confs/sub_….conf             subsets.py, 42 subsets
    per_face/sub_…/errors.csv    Estimate, 42 subsets
    roney/sub_i-j-k/errors.csv   estimator/roney.py, 20 triplets
  figures/                       once: analysis/analysis.py, tables and PNGs
  mesh/                          once: the 12 error PLYs, ErrorMaps from error_maps.py
```

The error PLYs are not made for every scenario: `error_maps.py` picks only 4
cases (see *Error PLYs*) and writes their `error_maps.txt` next to the
`errors.csv` of the case, so these 4 files exist only in
`aniso_zone_1/per_face/sub_0-1-2-3-4-5/`,
`aniso_zone_600/per_face/sub_0-1-2-3-4-5/` and, for the chosen triplet,
`aniso_zone_600/per_face/sub_i-j-k/` and `aniso_zone_600/roney/sub_i-j-k/`.

`run_all.sh` deletes `output/` before recomputing it, so no old
results end up in the figures.

`subsets.py SCENARIO` writes in `output/SCENARIO/confs/` one `.conf` for each
subset of at least 3 maps (the rows of
`simulator/stage1/pacing_sites.csv`; with six maps 20 + 15 + 6 + 1 = 42),
with `output_csv` = `output/SCENARIO/per_face/ID/errors.csv`. The ID is `sub_`
with the site indices joined by hyphens, e.g. `sub_0-2-4`, also the name of the
`.conf`. The six maps are `sub_0-1-2-3-4-5`.

```bash
python experiments/subsets.py aniso_zone_1
./estimator/build/Estimate output/aniso_zone_1/confs/*.conf
```

`estimator/roney.py experiments/roney.conf SCENARIO ...` applies method 2
of Roney et al. 2019 to all the map triplets of each scenario and writes
`output/SCENARIO/roney/sub_i-j-k/errors.csv`, with the same columns. The
keys of `roney.conf` are documented in the file.

## Analysis

`python analysis/analysis.py`, without arguments, reads the whole grid and
writes to `output/figures/`. Area-weighted statistics, errors as in
*Error PLYs*; q50, q90 and q99 on the absolute value, the signed
median of cv_l and ratio only in the tables. d = sqrt(4 A / (pi N)) is the
mean zone diameter in mm, A the total area of the mesh (with N = 1,
d = 123 mm).

- `per_face.csv`: one row per scenario and subset of the per-face
  estimator: non-estimable area and errors on the estimable faces of the
  subset.
- `comparison.csv`: one row per scenario, triplet and method (`per_face`,
  `roney`), with the non-estimable area of the method alone, the paired area
  (faces estimable by both methods with that triplet) and the errors on the
  paired faces. The rows with `sub` = `pooled` gather the paired faces
  of the 20 triplets of the scenario.

Plot 0 is three PNGs; plots 1 to 4 are four PNGs each: `_area` (non-estimable area, one
panel) and `_angle`, `_cv_l`, `_ratio`. In plots 1 and 2 these
have a single panel with q50, q90 and q99 together (circle, square,
triangle, Okabe-Ito colors), points only without lines, with the vertical
axis on a log scale and labels in plain numbers (1, 2, 5, 10...);
in plots 3 and 4 three panels q50, q90 and q99. The other vertical axes,
including the `_area` files, are linear and start at 0 (in plot 4 also
the horizontal one, with the same limits).

| file                     | content                                                |
|--------------------------|--------------------------------------------------------|
| `plot0_cond_errors.png`  | `aniso_zone_1`, faces with computed cond of the 42 subsets together, in 10 equal-area cond bins, at the median cond of the bin: three panels angle, cv_l, ratio with one box per bin on the estimable faces (q25–q75, line at q50, whiskers q10–q90, area-weighted; log on both axes) and in the title Spearman's ρ between cond and error; in a 2 × 2 square with the area panel: the % of area of the bin where the estimate is not an ellipse, i.e. the faces with cond but with smaller eigenvalue ≤ 1e-8 times the larger one (the estimated conic is a hyperbola, or an ellipse flat to numerical zero); the faces discarded because the smallest singular value is below threshold have no cond and do not appear |
| `plot0_maps_cond.png`    | `aniso_zone_1`: one box of cond (log) per k, on the faces with computed cond of all the subsets with k maps |
| `plot0_cond_area.png`    | `aniso_zone_1`, one point per subset from `per_face.csv`: cond_q90 (log) on the horizontal axis, non-estimable area on the vertical axis, color and marker by k; in the title Spearman's ρ over the 42 points |
| `plot1_maps_*`           | `aniso_zone_1`, as a function of k: one point per subset and quantile, staggered within each k |
| `plot2_zones_*`          | six maps, as a function of d (log): one point per scenario and quantile |
| `plot3_zones_maps_*`     | as a function of d (log): for each k the median over the subsets and a band from minimum to maximum |
| `plot4_roney_*`          | one point per triplet and scenario (one color and one marker per scenario): Roney on the horizontal axis, per-face on the vertical axis, with y = x; on the axes only 0, minimum, centroid (mean of the 80 points, cross) and maximum, with dotted projections and without grid |

Median, minimum and maximum over subsets count each subset once;
the area weighting applies within each subset. In plots 2 and 3 the
dashed line is the diameter of Roney's disc, 2 `patch.radius_mm`.

## Error PLYs

For MeshLab, which colors the faces with a single field, `quality`:

```bash
./estimator/build/ErrorMaps MESH.ply NUMBERS.txt PREFIX
```

with `MESH.ply` a `lat_ply` of the same mesh (only its geometry is read, no
LAT map) and `NUMBERS.txt` an `error_maps.txt` written by `error_maps.py`:
only numbers, one row per face in `face_id` order, `estimable angle cv_l ratio`,
with `0 0 0 0` on the non-estimable faces (no `nan`, which `>>` in C++ does not
read). `error_maps.py` reads the errors from the `errors.csv` of the case
(from Estimate or from `estimator/roney.py`, which compute them) with `load()`, imported from
`analysis/analysis.py`. The numbers
are written with `repr`, which reads back exactly as a double. `ErrorMaps` writes with `exportAsPly` (`estimator/src/io.cpp`) three
text PLYs (`format ascii 1.0`, written by happly, which adds a `comment` line),
one per error:

| file                    | per-face `quality`                           |
|-------------------------|----------------------------------------------|
| `PREFIX_angle.ply`      | fiber angle error, degrees                   |
| `PREFIX_cv_l.ply`       | relative error on CV_L, %, signed            |
| `PREFIX_ratio.ply`      | relative error on r = CV_L / CV_T, %, signed |

Header of each file:

```
element vertex 21811
property float x
property float y
property float z
property float nx
property float ny
property float nz
element face N
property list uchar int vertex_indices
property float quality
```

- Vertices: all of them, in the order of `lat_ply`, `x y z` in mm, with the
  per-vertex normals `nx ny nz`, unit and pointing outward, computed on the
  whole mesh, so a vertex left without faces still has a finite normal.
- Faces: only the estimable ones (`estimable = 1` in `NUMBERS.txt`), the same
  in the three files, in `face_id` order; `N` is their number. The vertex
  indices are those of `lat_ply`. The non-estimable faces are left out because
  MeshLab crashes on a NaN quality ("Colorize by face quality"): the holes in
  the surface are the non-estimable area. A written face with a non-finite
  quality stops `ErrorMaps` with an error naming the file and the `face_id`.
- Each triangle has its vertices in reverse order, `(a, c, b)`, with respect to
  `lat_ply`, hence face normals pointing outward, consistent with the
  per-vertex ones, and MeshLab shows the surface seen from outside.
- `quality` is the value of `NUMBERS.txt` rounded to float.

These PLYs are only for visualization: they must never be used as input to
any computation (reversed triangles, missing faces).

`error_maps.py` chooses the cases, writes for each one `error_maps.txt` next to
its `errors.csv` and prints a line `MESH NUMBERS PREFIX`, which `run_all.sh`
passes to `ErrorMaps`; it creates `output/mesh/` if needed. The PLYs are
`output/mesh/METHOD_SCENARIO_SUB_{angle,cv_l,ratio}.ply`, 12 in all:

1. per-face, six maps, `aniso_zone_1`;
2. per-face, six maps, `aniso_zone_600`;
3. and 4. per-face and Roney on the triplet of `aniso_zone_600` with the largest
   paired area (faces estimable by both methods, area-weighted,
   from the two `errors.csv` of the triplet).

The scenarios are constants at the top of `error_maps.py`.
